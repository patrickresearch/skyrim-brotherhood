# CK-Anleitung M0.6: Smoke-Test `NHV_Sys_Core`

**Ziel:** Ein Plugin `NightsHarvest.esp` mit einer Quest, die beim Spielstart läuft, `NHV_CoreScript` ausführt und ingame „Night's Harvest 0.0.1 loaded“ anzeigt. Damit ist die Kette Plugin → Script → BSA → FOMOD → Spiel einmal durchlaufen.

**Stand seit E17:** Claude hat das ESP selbst erzeugt (Spriggit, Text in `plugin-text/`). Du prüfst es einmal im Creation Kit und speicherst es dort, bevor weitergearbeitet wird (Ein-Schreiber-Regel). Es sind keine Records von Hand anzulegen.

**Voraussetzungen:**
- E05 entschieden: Master nur `Skyrim.esm` und `Update.esm`.
- `Data\NightsHarvest.esp` liegt im Repo und in der Dev-Kopie (`tools\sync_dev.ps1 -Direction ToDev -IncludeEsp`, Stand 22.09.: erledigt, die drei Fassungen sind hash-identisch).
- Weder das Live-Spiel noch Vortex laufen.

**Dauer (Schätzung):** 30 min für CK-Prüfung und Test.

## Record-Inventar

| EditorID | FormID (im Plugin) | Typ | Zweck | neu/ändern |
|---|---|---|---|---|
| `NightsHarvest.esp` | – | Plugin | Master `Skyrim.esm`, `Update.esm` | neu |
| `NHV_Cfg_Debug` | `000800` | GlobalVariable, Short, Wert 1 | Schalter für `[NHV]`-Logzeilen | neu |
| `NHV_Sys_Core` | `000801` | Quest, Start Game Enabled, Script `NHV_CoreScript` | System-Quest | neu |

Vanilla-Records werden nicht angefasst.

## Prüfen im Creation Kit (einmal)

1. **Creation Kit starten.** Über MO2 (Executable „Creation Kit“, MO2 setzt die Steam-ID selbst) oder direkt aus der Dev-Kopie (`ckpe_loader.exe`, ungetestet). Nie das CK aus dem Live-Spielordner. Bei MO2 landen neu erstellte Dateien in `C:\Dev\brotherhood-devenv\MO2\overwrite`; `tools\sync_dev.ps1 -Direction FromDev` findet sie dort.
2. **Plugin laden:** Datei → Daten. `Skyrim.esm` und `Update.esm` sind als Master markiert, `NightsHarvest.esp` als aktive Datei. Lädt das CK ohne Warnung oder Absturz? Warnungen bitte wörtlich zurückmelden.
3. **Global prüfen:** `NHV_Cfg_Debug`: Type Short, Value 1, Constant aus.
4. **Quest prüfen:** `NHV_Sys_Core`: Start Game Enabled an, Run Once aus, keine Stages, keine Aliase. Reiter „Scripts“: `NHV_CoreScript`, Property `NHV_Cfg_Debug` zeigt auf den Global `NHV_Cfg_Debug`.
5. **Speichern:** Datei → Speichern (auch ohne Änderung), dann das CK schließen. Das normalisiert die Datei durch das CK.

## Danach Sichern (Claude bzw. du)

1. `powershell -File tools\sync_dev.ps1 -Direction FromDev` holt das gespeicherte ESP ins Repo (überschreibt keine neuere Repo-Datei ohne `-Force`).
2. `powershell -File tools\plugin_text.ps1 -Direction ToText` schreibt den Text neu. Änderungen, die das CK gemacht hat, erscheinen im Git-Diff.
3. Commit auf `dev`: `[Core] Smoke-Test: CK-Prüfung von NightsHarvest.esp`.

## Prüfen im Spiel (Testprofil Clean, MO2-Profil `Default`)

**Vorbereitung:**
1. Sicherstellen, dass `NightsHarvest.esp` in der Dev-Kopie liegt (Sync siehe oben).
2. MO2 starten, in der Plugin-Liste `NightsHarvest.esp` aktivieren, neben `unofficial skyrim special edition patch.esp` und `SkyUI_SE.esp`.
3. Über den MO2-Eintrag **SKSE** starten (nicht `SkyrimSE.exe` direkt aus der Kopie).

**Schritte:**
1. Im Hauptmenü die Konsole (`^` oder `~`) öffnen und eine beliebige Zelle laden, z. B. `coc WhiterunBanneredMare` (Zellname im Zweifel prüfen).
2. Nach dem Laden oben links auf die Meldung achten.
3. In der Konsole `sqv NHV_Sys_Core` eingeben.
4. Speichern, Spiel beenden, das Papyrus-Log öffnen (Pfad in `docs/ENVIRONMENT.md`, nach dem ersten Testlauf bestätigen).
5. Denselben Spielstand laden.

**Erwartet:**
- Meldung „Night's Harvest 0.0.1 loaded“ einmal nach dem ersten Laden.
- `sqv` zeigt `NHV_Sys_Core` als laufend.
- Log enthält `[NHV] Maintenance done, mod 0.0.1, script version 1`.
- Beim erneuten Laden keine zweite Meldung.
- Keine Papyrus-Fehler mit `NHV_`.

**Bitte zurückmelden:** Log-Zeilen mit `[NHV]` und jede Zeile mit `NHV_`, die `error` oder `warning` enthält; die Ausgabe von `sqv NHV_Sys_Core`; ob die Meldung erschien. Danach `powershell -File tools\verify_live_untouched.ps1` ausführen und das Ergebnis mitschicken. Zusätzlich BT15 (SKSE fehlt) laut `docs/tests/M0.6.md`.

**FOMOD-Test:** `dist\NightsHarvest-0.0.1.7z` liegt bereit (`tools\package.ps1`, Stand 22.09.). In MO2 über „Mod aus Archiv installieren“ einspielen; der Installer sollte ohne Fragen durchlaufen. Der Test in Vortex gehört zum Exit-Kriterium von M0 und läuft erst, wenn ein Vortex-Profil außerhalb des Live-Spiels feststeht.
