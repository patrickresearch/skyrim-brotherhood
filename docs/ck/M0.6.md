# CK-Anleitung M0.6: Smoke-Test `NHV_Sys_Core`

**Ziel:** Ein leeres Plugin `NightsHarvest.esp` mit einer Quest, die beim Spielstart läuft, `NHV_CoreScript` ausführt und ingame „Night's Harvest 0.0.1 loaded“ anzeigt. Damit ist die Kette Creation Kit → Script → BSA → FOMOD → Spiel einmal durchlaufen.
**Voraussetzungen:**
- `powershell -File tools\build.ps1` läuft sauber (Stand 22.09.: 2 Scripts, 0 Fehler).
- Scripts in der Dev-Kopie: `powershell -File tools\sync_dev.ps1 -Direction ToDev` (kopiert `.pex` und `NHV_*.psc` nach `C:\Dev\brotherhood-devenv\SkyrimSE-Dev\Data`).
- **E05 (Master-Dateien)** ist offen. Diese Anleitung geht von der Empfehlung aus: nur `Skyrim.esm` und `Update.esm`. Bitte vor Schritt 1 bestätigen.
- Es läuft weder das Live-Spiel noch Vortex während der Arbeit im CK.

**Dauer (Schätzung):** 1 h für CK und Test.

## Record-Inventar

| EditorID | Typ | Zweck | Quest | neu/ändern |
|---|---|---|---|---|
| `NightsHarvest.esp` | Plugin | Masters: `Skyrim.esm`, `Update.esm` | – | neu |
| `NHV_Cfg_Debug` | GlobalVariable (Short) | Schalter für `[NHV]`-Logzeilen, hier Wert 1 | – | neu |
| `NHV_Sys_Core` | Quest | Start Game Enabled, trägt `NHV_CoreScript` | – | neu |

Vanilla-Records werden nicht angefasst.

## Schritte

1. **Creation Kit starten.** Über MO2 (Executable „Creation Kit“, MO2 setzt die Steam-ID selbst) oder direkt aus der Dev-Kopie (`ckpe_loader.exe`, ungetestet). Nie das CK aus dem Live-Spielordner.
   - Bei MO2 landen neu erstellte Dateien im Ordner `C:\Dev\brotherhood-devenv\MO2\overwrite`. `tools\sync_dev.ps1 -Direction FromDev` findet sie dort.
2. **Plugin anlegen:** Menü Datei → Daten (Data). Nur `Skyrim.esm` und `Update.esm` anhaken. `Dawnguard.esm`, `HearthFires.esm`, `Dragonborn.esm` bleiben aus (E05). Mit OK laden.
3. **Global anlegen:** Object Window, Bereich für Globals (Name im CK prüfen), Rechtsklick → Neu.
   | Feld | Wert |
   |---|---|
   | ID | `NHV_Cfg_Debug` |
   | Type | Short |
   | Value | 1 |
   | Constant | aus |
4. **Quest anlegen:** Object Window → Quest (unter „Character“, Name im CK prüfen) → Rechtsklick → Neu.
   | Feld (Quest Data) | Wert |
   |---|---|
   | Quest ID | `NHV_Sys_Core` |
   | Quest Name | leer lassen (System-Quest, kein Journal-Eintrag) |
   | Priority | 0 |
   | Start Game Enabled | **an** |
   | Run Once | aus |
   Keine Stages, keine Aliase, kein Dialog. Deshalb ist keine SEQ-Datei nötig.
5. **Script anhängen:** Reiter „Scripts“ der Quest → Add → `NHV_CoreScript`. Erscheint das Script nicht, fehlt die `.pex` in der Dev-Kopie (`sync_dev.ps1 -Direction ToDev`).
6. **Property füllen:** `NHV_CoreScript` markieren → Properties → `NHV_Cfg_Debug` → Edit Value → Global `NHV_Cfg_Debug` wählen. Die Konstanten `VERSION` und `VERSION_TEXT` sind AutoReadOnly und erscheinen nicht.
7. **Speichern:** Datei → Speichern, Name `NightsHarvest.esp`. Das CK beendet man danach regulär.

## Speichern & Sichern

1. `powershell -File tools\sync_dev.ps1 -Direction FromDev` holt das ESP nach `Data\NightsHarvest.esp` im Repo (überschreibt keine neuere Repo-Datei ohne `-Force`).
2. Claude führt Spriggit-Serialize aus (`docs/ENVIRONMENT.md`) und prüft, dass nur die drei Records im Plugin stehen.
3. Commit auf `dev`: `[Core] Smoke-Test: NHV_Sys_Core und NHV_Cfg_Debug`.

## Prüfen im Spiel (Testprofil Clean, MO2-Profil `Default`)

**Vorbereitung:**
1. `powershell -File tools\sync_dev.ps1 -Direction ToDev -IncludeEsp`, damit ESP und Scripts in der Dev-Kopie liegen (falls das CK das ESP nicht schon dort gespeichert hat).
2. MO2 starten, in der Plugin-Liste `NightsHarvest.esp` aktivieren, neben `unofficial skyrim special edition patch.esp` und `SkyUI_SE.esp`.
3. Über den MO2-Eintrag **SKSE** starten (nicht `SkyrimSE.exe` direkt aus der Kopie).

**Schritte:**
1. Im Hauptmenü die Konsole (`^` oder `~`) öffnen und eine beliebige Zelle laden, z. B. `coc WhiterunBanneredMare` (Zellname im Zweifel prüfen).
2. Nach dem Laden oben links auf die Meldung achten.
3. In der Konsole `sqv NHV_Sys_Core` eingeben.
4. Speichern, Spiel beenden, das Papyrus-Log öffnen (Pfad in `docs/ENVIRONMENT.md`, nach dem ersten Testlauf bestätigen).
5. Denselben Spielstand laden.

**Erwartet:**
- Meldung „Night's Harvest 0.0.1 loaded“ einmal nach dem ersten Laden.
- `sqv` zeigt `NHV_Sys_Core` als laufend.
- Log enthält `[NHV] Maintenance done, mod 0.0.1, script version 1`.
- Beim erneuten Laden keine zweite Meldung.
- Keine Papyrus-Fehler mit `NHV_`.

**Bitte zurückmelden:** Log-Zeilen mit `[NHV]` und jede Zeile mit `NHV_`, die `error` oder `warning` enthält; die Ausgabe von `sqv NHV_Sys_Core`; ob die Meldung erschien. Danach `powershell -File tools\verify_live_untouched.ps1` ausführen und das Ergebnis mitschicken.

**FOMOD-Test:** Sobald das ESP vorliegt, baut `powershell -File tools\package.ps1` `dist\NightsHarvest-0.0.1.7z`. Diesen in MO2 über „Mod aus Archiv installieren“ einspielen (Installer sollte ohne Fragen durchlaufen). Der Test in Vortex gehört zum Exit-Kriterium von M0 und läuft erst, wenn ein Vortex-Profil außerhalb des Live-Spiels feststeht.
