# M2.0 – Map Table (E42): CK-Anleitung und Test

Nach Q01 wählt der Spieler den nächsten Contract am Map Table im Ledger Room. Jetzt nur Q02 (Windhelm);
Q03–Q05 kommen mit M2.3–M2.5 dazu, ohne dass das Script neu verdrahtet wird.

**Ablauf ingame:** Tisch aktivieren → Menü (Windhelm, Winterhold, Riften, The Reach, Step away) →
„Windhelm“ startet `NHV_Q02_ColdWaters` auf Stage 10 → Veyra hält das Briefing über das vorhandene
ForceGreet-Package `NHV_Pkg_Q02_BriefGreet` (Zeilen `NHV_Q02_010_01–03`).

**Script-Regeln:** Freigabe erst bei Q01 Stage 100. Nur ein Contract gleichzeitig. Ein abgeschlossener Pin ist weg.
Ohne lebende Veyra startet nichts. Ist Veyra weiter als 1200 Einheiten weg oder in einer anderen Zelle,
wird sie zum Marker `NHV_Mk_MapTable_Veyra` bewegt.

## Übersicht der Schritte

| Nr. | Was | Wo |
|---|---|---|

## Schritt 1 – Message `NHV_Msg_MapTable`

**Wo:** Object Window → Miscellaneous → Message → Rechtsklick in die Liste → New.

- [ ] **ID:** `NHV_Msg_MapTable`
- [ ] **Message Text:** `Veyra's map of Skyrim. Four pins, four names. One blade at a time.`
- [ ] **Message Box** aktivieren (nicht Auto-Display).
- [ ] **Buttons** in genau dieser Reihenfolge anlegen. Den Text trägst du **nicht in der Tabelle** ein: Zeile anklicken, dann ins Feld **Item Text** unter der Tabelle tippen. Fehlende Zeile: Rechtsklick in die leere Tabelle → New. Keine Item Conditions:

| Index | Button-Text |
|---|---|
| 0 | Windhelm |
| 1 | Winterhold |
| 2 | Riften |
| 3 | The Reach |
| 4 | Step away |

Die Reihenfolge ist fest verdrahtet: Das Script wertet Index 0–3 als Q02–Q05, jeden anderen Index als Abbruch.
- [ ] OK.

## Schritt 2 – Activator `NHV_Act_MapTable`

**Wo:** Object Window → WorldObjects → Activator → Rechtsklick → New.

- [ ] **ID:** `NHV_Act_MapTable`
- [ ] **Name:** `Map Table` (erscheint beim Zielen als „Map Table“ mit Aktivierungshinweis).
- [ ] **Model (Weg A, Model-Auswahl geht nicht): Record duplizieren statt Model wählen.** Object Window → WorldObjects → Activator → Filter „Map“ oder „Table“. Einen passenden vorhandenen Activator (oder unseren `NHV_Act_Q02_TrackClue1` als Platzhalter) mit Rechtsklick → **Duplicate** kopieren. Im neuen Record ID auf `NHV_Act_MapTable` und Name auf `Map Table` ändern. Ein evtl. mitkopiertes Script im Reiter Scripts löschen. Der Duplikat-Record gehört uns, das Original bleibt unverändert (Regel 1).
- [ ] **Model (Weg B):** Wenn auch das nicht geht, den Activator ganz ohne Model-Arbeit als Duplikat von `NHV_Act_Q02_TrackClue1` anlegen und in Schritt 4 unsichtbar machen: In der platzierten Referenz (Doppelklick) **Initially Disabled** bleibt aus, aber das Feld **Visible When Distant** aus und in der Referenz-Registerkarte **Scale** auf den Bedarf setzen. Alternativ das Modell des vorhandenen Tisches im Raum benutzen (Tisch im Render Window anklicken, Referenz-Fenster) und Script direkt an dessen Referenz hängen, siehe Schritt 3, Weg B.
- [ ] Wenn du die Fehlermeldung des Model-Dialogs mitteilst, kann ich gezielter helfen.
- [ ] **OK** klicken, um den Record zu erzeugen. Erst danach Schritt 3.

## Schritt 3 – Script anhängen, Properties Teil A

**Weg A (am Base-Record):** Object Window → Activator → `NHV_Act_MapTable` per Doppelklick **erneut öffnen** (neue Records erlauben Scripts oft erst nach dem ersten OK) → Reiter **Scripts** → Add. Im Add-Fenster `NHV_MapTableScript` suchen. Geht Rechtsklick immer noch nicht: unten im Reiter den Button **Add** statt Rechtsklick benutzen.

**Weg B (an der platzierten Referenz):** Wie beim Leichen-Script in `M2.2-…-Teil2` (Abschnitt A3): Referenz im Render Window doppelklicken → Reiter **Scripts** → **Add** → `NHV_MapTableScript`. Die Properties werden dann an dieser Referenz gesetzt, auch `VeyraTableMarker` (Schritt 5). Weg B ist der zuverlässigere. Weg B geht nach Schritt 4; Schritt 3 und 4 dann tauschen.

Danach Script markieren → **Properties** → jede Zeile → Edit Value:

| Property | Wert | Wo im Dialog suchen |
|---|---|---|
| `PlayerRef` | `PlayerRef` (Referenz 000014) | Liste „Persistent References“ / Suchfeld |
| `NHV_Cfg_Debug` | `NHV_Cfg_Debug` | Global Variable |
| `Core` | `NHV_Sys_Core` | Quest |
| `NHV_Msg_MapTable` | `NHV_Msg_MapTable` | Message |
| `Q01` | `NHV_Q01_TheUnansweredSacrament` | Quest |
| `Q02` | `NHV_Q02_ColdWaters` | Quest |
| `Q03`, `Q04`, `Q05` | leer lassen | – |
| `VeyraTableMarker` | jetzt leer lassen (Schritt 5) | – |

- [ ] Alle sechs Werte gesetzt, Q03–Q05 bewusst leer.
- [ ] OK im Script-Properties-Fenster, OK im Activator-Fenster.

## Schritt 4 – Platzieren im Ledger Room

**Wo:** Cell View → Interiors → die Zelle, in der Veyras Ledger Room liegt (aktuell die Deep-Sanctuary-Zelle `NHV_DeepSanctuaryCell`, die Markarth-Kopie). Im Render Window an die Stelle des Map Table navigieren.

- [ ] `NHV_Act_MapTable` aus dem Object Window ins Render Window ziehen. Position auf den Tisch, Höhe so, dass der Cursor beim Zielen den Hinweis zeigt.
- [ ] Optional bei Bedarf **Persistent** setzen (Referenz-Fenster, Häkchen „Persistent“), sonst nicht nötig.
- [ ] **XMarker** aus dem Object Window (WorldObjects → Static → `XMarker`) ins Render Window ziehen, neben den Tisch dorthin, wo Veyra stehen soll, wenn sie den Spieler anspricht (etwa 1–2 m vom Tisch, auf dem Boden, gut erreichbar, im Navmesh). Ausrichtung Richtung Tisch.
- [ ] Referenz des XMarkers doppelklicken und im Feld **EditorID** eintragen: `NHV_Mk_MapTable_Veyra`.
- [ ] Bei Bedarf beide Referenzen kontrollieren: sie liegen im Ledger Room, nicht in einer Wand.

Beim späteren Umzug in die echte Deep Sanctuary: Referenzen mitnehmen, FormIDs nicht neu vergeben.

## Fehlersuche

| Symptom | Ursache | Abhilfe |
|---|---|---|
| Kein Aktivierungshinweis am Tisch | Referenz nicht platziert oder Modell zu klein / hinter dem Tisch | Schritt 4 prüfen, Activator größer bzw. näher setzen |
| Menü zeigt falsche Buttons oder wählt falschen Contract | Reihenfolge der Buttons | Schritt 1, Index 0–4 |
| Meldung „old marks“ trotz Q01-Abschluss | Q01 Stage 100 nie gesetzt oder Property `Q01` leer | `getstage NHV_Q01_TheUnansweredSacrament`; Schritt 3 |
| Q02 startet, Veyra spricht nicht | ForceGreet greift nicht (Veyra zu weit, Package fehlt am Alias) | Log auf „VeyraTableMarker“ prüfen; Schritt 5 und 6 |
| Script nicht auswählbar im CK | `.psc` nicht in `Data\Source\Scripts` der Dev-Kopie | Schritt 0 |

## Später

- **Q03–Q05:** im jeweiligen Paket im Activator-Script die Property `Q03` / `Q04` / `Q05` setzen. Der Contract startet dann wie Q02 mit Stage 10 als Briefing. Kein Script-Umbau.
- **Freigabe erst nach Debrief:** aktuell genügt Q01 Stage 100. Soll erst der Debrief (Zeile 100_20 „Choose where we go next“) freischalten, legt der Q01-V2-Einbau eine Global `NHV_Q01_DebriefDone` an und das Script prüft sie zusätzlich.
